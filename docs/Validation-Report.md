## What these results do not establish

The offline hour advances musical frames faster than real time. It does **not** establish one hour of real iPhone foreground stability, thermal behavior or hardware underrun performance. The simulator tests establish functional UI flows, not acoustic timing or physical multitouch. A signed build does not establish a successful installation.

Still required with the owner's real files and unlocked phone:

- Integrate the remaining two kits; verify aliases/tom order, hashes, audio attacks, hats, stereo and cross-kit chains by listening.
- Measure median/p95 touch-to-audible latency on speaker and a wired/USB route using externally observed touch/audio timing; target ≤25/40 ms. No acoustic latency number is currently claimed.
- Measure visual-to-audible phase (target ≤50 ms); report actual route/rate/buffer and the contribution of system output latency.
- Perform four-finger chords, VoiceOver reading order, reduced-motion/manual contrast checks, and room/cymbal/decay listening.
- Test silent switch, route unplug/reconnect, Bluetooth, calls, Control Center, lock/unlock and media-services reset. UI automation covers Home-screen deactivation only.
- Run 60 minutes of real-time foreground playback, then Instruments allocations/CPU/underrun assessment; verify idle-timer behavior beyond the normal auto-lock interval. Measure resident memory with all real kits (<300 MiB target), startup/kit readiness and durable save times on the phone.
- Demonstrate saved draft conflict recovery and low-storage handling on-device; the automated write-failure and future-schema checks exercise the repository boundary on the host.

There are no stub save/play controls or hidden TODO implementations. The remaining release gates are asset delivery and physical-device verification; the normal simulator workflows are usable now.
